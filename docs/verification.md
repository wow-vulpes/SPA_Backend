# Соответствие техническому заданию

Реализована backend-часть задания на Java 21, Spring Boot, Maven,
PostgreSQL/Hibernate, Lombok, MapStruct, JUnit и Mockito. Это Java-адаптация
исходного Python-стека: Bean Validation вместо Pydantic, Flyway вместо
Alembic, JUnit вместо pytest. Расчёты выполняются детерминированными функциями.

| Пункт задания | Реализация |
| --- | --- |
| POST /api/movements и пересчёт остатка | Пять типов движений, атомарная запись заголовка и распределений |
| GET /api/movements | SKU/объект/тип/период, limit/offset/total |
| GET /api/stock | Остатки из журнала, расход за 90 полных дней, дни запаса, ближайший срок |
| GET /api/stock/{sku} | Объекты и партии, сроки, цены, накладные |
| POST /api/forecast | Горизонт в календарных месяцах, спрос, страховой запас, поставки, точка заказа, закупка с MOQ/упаковкой, стоимость, даты |
| JSON прогноза | name/unit, period, поля примера ТЗ, структурированный explanation, warnings с level/message |
| GET /api/alerts | Запас меньше срока поставки, сроки партий, отсутствие движения; важность и показатели |
| FEFO | Ближайший срок, затем поступление и ID; просрочка недоступна для consume, отдельный writeoff |
| Ошибки | Неизвестные ссылки 404, дубль документа 409, неверный ввод/нехватка 422, повреждённый JSON 400 |
| Отдельные расчётные функции | ForecastCalculator, StockMetrics, FefoAllocator; unit-тесты без HTTP |
| PostgreSQL и миграции | Шесть таблиц, Flyway V1, Hibernate validate, ограничения, индексы, транзакции |
| Одна команда запуска и начальные данные | docker compose up, атомарный demo-загрузчик только для пустой базы |
| README и окружение | Запуск, тесты, технологии, архитектура, .env.example, demo-сценарий |

Подробные сценарии и тесты: [test-matrix.md](test-matrix.md).
Контракты: [movements](api-movements.md), [stock](api-stock.md),
[forecast](api-forecast.md), [alerts](api-alerts.md).

## Границы реализации

- Горизонт прогноза задаётся одним из значений 1/3/6/12 месяцев от текущей
  бизнес-даты. Произвольная начальная дата и горизонт в днях не предусмотрены.
- Срок поставки, MOQ, упаковка и открытые поставки поступают в запросе
  прогноза. Для alerts срок поставки — параметр запроса с конфигурационным
  значением по умолчанию. Реестра поставщиков и заказов нет.
- Остаток текущий; API не восстанавливает исторический склад на произвольную
  дату. Списание прошло в хронологическом порядке, обратная вставка запрещена.
- Общая формула объёма и календарная проверка рисков разделены. Будущая
  просрочка или поздняя поставка могут дать дефицит даже при нулевой
  агрегатной закупке; это явно отражается в предупреждениях.
- Не реализованы интерфейс/чат, автоматические заказы, сезонная модель,
  бюджетный лимит, категории и экспорт. Они относятся к более широкому
  описанию продукта, а не к реализованному набору REST-эндпоинтов.
- Фильтруемые списки при неизвестных кодах возвращают пустую страницу;
  обращения к конкретной позиции и операции записи/прогноза — 404.
- Локальная публикация API — только localhost. Авторизация и публичное
  размещение не включены в этот вариант приложения.

Успех тестов подтверждает проверенные сценарии, но не гарантирует отсутствие
всех возможных дефектов и не доказывает точность прогнозирования на реальных данных.

# Регистрация движений

`POST /api/movements`, Content-Type: application/json. Успех — HTTP 201.
Справочники product и location должны существовать. API справочников и
загрузка демонстрационного набора пока не реализованы.

Поступление новой партии:

```json
{
  "sku": "OIL-001",
  "location": "MS-01",
  "operation_date": "2026-09-28",
  "type": "receipt",
  "quantity": 10.5,
  "document_number": "RECEIPT-001",
  "batch": {
    "number": "B-001",
    "expires_on": "2027-09-28",
    "unit_price": 1259.05,
    "invoice_number": "INV-001"
  }
}
```

Пример ответа (ID назначает БД):

```json
{
  "id": 1,
  "sku": "OIL-001",
  "location": "MS-01",
  "current_stock": 10.5,
  "available_stock": 10.5,
  "allocations": [{"batch_id": 1, "quantity_delta": 10.5}]
}
```

| type | Выбор партии | quantity |
| --- | --- | --- |
| receipt | Ровно одно: batch с реквизитами либо batch_id существующей партии | > 0 |
| consume | Без batch и batch_id: автоматический FEFO | > 0 |
| writeoff | batch_id списываемой партии | > 0 |
| return | batch_id исходной партии | > 0 |
| correction | batch_id корректируемой партии | Ненулевое знаковое значение |

Расход использует те же общие поля, например type=consume, quantity=3,
новый document_number; поле batch отсутствует. Остальные операции используют
batch_id вместо batch. Тип нечувствителен к регистру. Ключи и номера
очищаются от краевых пробелов, но остаются чувствительными к регистру.

FEFO: срок годности, дата первого поступления, ID партии. В день истечения
партия доступна. При историческом проведении годность проверяется на дату
операции. Дата не может быть будущей или раньше последней операции позиции;
одинаковая дата разрешена. Поэтому журнал можно загружать только последовательно.
Ответ содержит текущие остатки; available_stock исключает просрочку на сегодня
в APP_TIME_ZONE. Историческим снимком этот ответ не является.

Возврат означает возврат неиспользованного товара в исходную партию, включая
просроченную. Поступление просроченного товара допускается для отражения факта.
Просрочка увеличивает физический остаток, но недоступна для текущего consume.
Writeoff и отрицательная correction не могут превысить остаток выбранной партии.
Повтор номера партии при receipt допустим только с неизменными реквизитами;
цена сравнивается численно. Дата первого поступления сохраняется.

Количество: максимум 13 целых и 6 дробных цифр; цена: 15 и 4, RUB за единицу,
неотрицательная. Лишняя точность отклоняется до записи, округления API нет.

## Ошибки

| HTTP | Причина |
| --- | --- |
| 400 | Повреждённый или отсутствующий JSON |
| 404 | Неизвестный SKU, объект или batch_id |
| 409 | Повтор глобального номера документа либо конфликт блокировки |
| 422 | Неверные поля, хронология, реквизиты партии или нехватка |
| 500 | Непредвиденная ошибка; подробности только в журнале сервера |

```json
{
  "status": 422,
  "code": "INSUFFICIENT_STOCK",
  "message": "Недостаточно доступного остатка",
  "available_quantity": 2.5,
  "violations": []
}
```

Клиент ориентируется на status/code; текст message может изменяться.
available_quantity при consume — сумма подходящих партий, при writeoff или
отрицательной correction — остаток указанной партии. При валидации violations
содержит field/message; необязательное available_quantity отсутствует.

Документ не является ключом идемпотентного повтора: повтор возвращает 409.
Позиция блокируется до завершения транзакции; движение и все распределения
записываются вместе. Ошибка откатывает также созданные партию и позицию.
Гарантии действуют для записи через сервис; прямой SQL может обойти бизнес-правила.
Авторизация и публичное размещение API не входят в этот шаг.

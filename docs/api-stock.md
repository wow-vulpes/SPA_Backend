# Остатки и партии

## GET /api/stock

Одна строка — зарегистрированная позиция SKU/объект, включая нулевые остатки.
Товары без позиций не создают искусственных строк для всех салонов.

| Параметр | Правило |
| --- | --- |
| sku | Необязательный точный фильтр, 1–64 символа, краевые пробелы удаляются |
| location | Необязательный код объекта, те же правила |
| limit | 1–100; по умолчанию 50 |
| offset | 0–2147483647; по умолчанию 0 |

Регистр SKU/объекта учитывается. Явный пустой параметр — 422,
code=INVALID_STOCK_FILTER. Неизвестный код в фильтре — 200 и пустая страница.
Нулевой символ в фильтре запрещён: 422, code=INVALID_FIELD.
Порядок: SKU, затем код объекта по возрастанию в сортировке PostgreSQL.
Total — количество позиций с учётом фильтров, до пагинации.

```http
GET /api/stock?sku=OIL&location=SPA&limit=20&offset=0
```

```json
{
  "as_of": "2026-09-29",
  "consumption_from": "2026-07-01",
  "consumption_to": "2026-09-28",
  "items": [{
    "sku": "OIL",
    "name": "Oil",
    "unit": "ml",
    "location": "SPA",
    "location_name": "Spa",
    "current_stock": 709,
    "available_stock": 704,
    "average_daily_consumption": 2,
    "days_of_stock": 352,
    "nearest_expiry": "2026-09-28"
  }],
  "total": 1,
  "limit": 20,
  "offset": 0
}
```

## Правила расчёта

- Сегодня определяется через Clock в APP_TIME_ZONE, по умолчанию Europe/Moscow.
  Дата фиксируется один раз для всего ответа. Это текущий остаток, не исторический срез.
- current_stock — сумма quantity_delta всех распределений, включая просрочку.
- available_stock исключает партии, срок которых раньше сегодня; день истечения включён.
- average_daily_consumption = сумма quantity заголовков CONSUME за интервал
  [сегодня − 90 дней; сегодня) / 90. Сегодня не входит. Receipt, writeoff,
  return и correction не меняют эту статистику. Расход из нескольких партий
  учитывается один раз. Дни без операций включены в делитель, новая позиция
  также использует 90 дней; недостаток истории может занижать оценку спроса.
- days_of_stock = available_stock × 90 / сумма consume за тот же интервал.
  При нулевом расходе — null. При положительном расходе и нулевом доступном
  остатке — 0. Средний расход округляется HALF_UP до 6 дробных цифр, дни — до 2.
  Дни рассчитываются до округления среднего: очень малый спрос не превращается
  в деление на ноль. Поэтому отображаемый средний может округлиться до 0,
  когда days_of_stock ещё определён.
- nearest_expiry — минимальный срок партии с положительным физическим
  остатком, включая просроченные. Пустые партии исключаются; если подходящих
  партий нет, возвращается null.

Запас в днях — оценка при неизменном среднем спросе. Он не моделирует будущую
просрочку, загрузку SPA, поставки или сезонность. Это не прогноз закупки шага 6.

## GET /api/stock/{sku}

Возвращает товар и все его зарегистрированные позиции с партиями:

```json
{
  "sku": "OIL",
  "name": "Oil",
  "unit": "ml",
  "as_of": "2026-09-29",
  "consumption_from": "2026-07-01",
  "consumption_to": "2026-09-28",
  "locations": [{
    "stock": {
      "sku": "OIL", "name": "Oil", "unit": "ml",
      "location": "SPA", "location_name": "Spa",
      "current_stock": 10, "available_stock": 10,
      "average_daily_consumption": 0, "days_of_stock": null,
      "nearest_expiry": "2026-12-31"
    },
    "batches": [{
      "batch_id": 1, "batch_number": "B-1",
      "received_on": "2026-09-01", "expires_on": "2026-12-31",
      "unit_price": 12.3456, "invoice_number": "INV-1",
      "current_stock": 10, "available_stock": 10, "expired": false
    }]
  }]
}
```

Каждый stock имеет тот же контракт, что строка items списка.
Объекты сортируются по коду; партии — по сроку, дате поступления и ID.
Нулевые и просроченные партии включены. Цена — историческая цена партии в RUB
за единицу товара. У просроченной партии available_stock=0, expired=true.
У позиции без партий batches=[]; у товара без позиций locations=[].
Неизвестный SKU в пути возвращает 404, code=SKU_NOT_FOUND.

Все чтения одного ответа согласованы транзакцией REPEATABLE_READ. Между
отдельными запросами страницы снимок не сохраняется. Список ограничен limit;
детализация одного SKU возвращает все его партии без пагинации. Большие архивы
и нагрузочные пределы ещё не измерялись. GET не меняет складской журнал.

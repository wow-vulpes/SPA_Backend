# SPA Inventory & Procurement Assistant

Java 21 / Spring Boot 4.0.8 / PostgreSQL 17.11. Реализованы инфраструктура и
учётная модель: товары, объекты, позиции, партии, движения и распределения.
Реализован POST /api/movements: пять типов операций, FEFO, проверки и
транзакционная защита. GET /api/movements предоставляет историю с фильтрами,
limit/offset/total. [Контракт движений](docs/api-movements.md).
GET /api/stock показывает остатки и расход; GET /api/stock/{sku} — партии
по объектам. [Контракт остатков](docs/api-stock.md).
POST /api/forecast рассчитывает потребность, упаковки, стоимость и даты заказа,
показывает объяснения и риски. [Контракт прогноза](docs/api-forecast.md).
GET /api/alerts показывает дефицит, сроки партий и отсутствие движения
с важностью и исходными показателями. [Контракт предупреждений](docs/api-alerts.md).

## Запуск

Нужен Docker с Compose. Из корня репозитория:

```bash
docker compose up
```

В другом терминале: `curl --fail http://localhost:8080/actuator/health`.
После изменения кода используйте `docker compose up --build`. Для проверки
готовности можно добавить `--wait --wait-timeout 120`; таймаут относится к
готовности контейнеров, скачивание и сборка могут занять больше времени.

Первый запуск скачивает образы и зависимости. Compose использует локальные
демонстрационные параметры по умолчанию; переопределить их можно в `.env`,
созданном на основе `.env.example`. Файл `.env` не коммитится.

`docker compose down` останавливает контейнеры и сохраняет том PostgreSQL.
Единая миграция V1 применяется автоматически. Товарных demo-данных пока нет;
их загрузка запланирована на шаг 8. API опубликован только на localhost.

Если база уже работала со старой V1/V2, см. [переход к единой V1](docs/migrations.md).
После изменения набора миграций локально нужен `./mvnw clean verify`, чтобы
удалить прежние SQL-файлы из target.

## Проверки

Для локальной сборки нужен JDK 21 и доступ к Maven Central. Убедитесь,
что `JAVA_HOME` указывает на JDK 21; `./mvnw -version` показывает фактическую
Java и Maven 3.9.16.

```bash
./mvnw test
./mvnw verify
```

`test` выполняет unit-тесты без Docker. `verify` дополнительно выполняет
`*IT` через Failsafe: временные PostgreSQL 17.11, миграции, JPA и ограничения,
агрегаты, транзакции и блокировки. Эти тесты не обращаются к базе Compose
и автоматически удаляют свои контейнеры. Если Docker недоступен, verify
завершается ошибкой. H2 не используется.

Spotless проверяет формат, SpotBugs — ошибки анализа, Enforcer — версии.
Исправление формата: `./mvnw spotless:apply`. Отчёты: `target/surefire-reports`,
`target/failsafe-reports`, `target/site/jacoco/index.html`. Числовой порог
покрытия не установлен. CI выполняет ту же команду verify; фактический
удалённый запуск зависит от push пользователя.

## Конфигурация

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| APP_PORT | Порт на хосте; внутри Compose приложение слушает 8080 | 8080 |
| APP_TIME_ZONE | Бизнес-часовой пояс | Europe/Moscow |
| APP_ALERTS_SHORTAGE_DAYS | Горизонт проверки дефицита, 1–3650 дней | 30 |
| APP_ALERTS_EXPIRY_DAYS | Порог приближения срока годности, 0–3650 дней | 30 |
| APP_ALERTS_INACTIVITY_DAYS | Порог отсутствия любых движений, 1–3650 дней | 90 |
| DB_NAME | Имя базы в Compose | spa |
| DB_USER | Пользователь PostgreSQL | spa |
| DB_PASSWORD | Пароль PostgreSQL для локального demo | spa |
| DB_URL | JDBC URL при запуске вне Compose | jdbc:postgresql://localhost:5432/spa |

В Compose DB_URL формируется с хостом `postgres` и DB_NAME. Порт БД наружу
не публикуется. Для запуска из IDE задайте DB_URL доступной PostgreSQL и
DB_USER/DB_PASSWORD в окружении процесса. Spring не читает `.env` автоматически.

## Архитектура и данные

Один Maven-модуль. Пакеты `catalog`, `movement` и `stock` содержат текущую
persistence-модель. Hibernate отображает сущности, Flyway управляет схемой;
`ddl-auto=validate` запрещает автоматическое изменение таблиц Hibernate.
Lombok сокращает конструкторы/аксессоры. MapStruct преобразует DTO движений.

Остаток вычисляется суммой `movement_allocation.quantity_delta`. В строке
позиции и партии нет изменяемого поля остатка. Составные внешние ключи
запрещают смешивание партий и движений разных позиций. Просроченные партии
участвуют в физическом остатке, но исключаются из доступного.

[Модель и границы гарантий](docs/data-model.md),
[требования](docs/requirements.md), [матрица проверок](docs/test-matrix.md).
MovementService обеспечивает FEFO, проверку нехватки, хронологии и
соответствие распределений движению. HTTP-тесты на PostgreSQL проверяют
также конкурентные запросы и откат. История читает заголовки движений в
стабильном порядке даты/ID; count и страница согласованы одним снимком БД.
Остатки считаются по партиям, средний расход — отдельно по заголовкам CONSUME
за 90 полных дней. Объединение агрегатов не умножает расход на число партий.
Прогноз использует календарный горизонт и точный средний расход; дневная
симуляция выявляет дефицит из-за сроков поставки и годности. Параметры закупки
и ожидаемые поставки передаются в запросе. Реестр заказов и автоматическое
размещение заказа не реализованы. Справочники и demo-набор пока нужно подготовить отдельно.
